### Poprawiona procedura — wystarcza hasło archiwum

Pakiet zawiera `MANIFEST.txt`, `medzuslovjansky-release.jks`,
`medzuslovjansky-release.password.txt` i **`keystore.properties` z konfiguracją
podpisu**. Wcześniejszy bootstrap kopiował tylko JKS i usuwał resztę po rozpakowaniu.
Stąd zbędne poszukiwanie osobnego hasła JKS. Pierwsza ręczna próba otwarcia JKS
się nie powiodła; konfiguracja odczytana z tego samego backupu zadziałała.

Nowy [`tools/sign_apk_from_backup.py`](../tools/sign_apk_from_backup.py) pobiera
backup z `hetz`, sprawdza jego sumę i zgodność lokalnego JKS, odczytuje konfigurację
wyłącznie w pamięci i przekazuje hasła do narzędzi przez standardowe wejście.
GPG może poprosić w `pinentry` o **hasło archiwum**. Hasła JKS nie są wyświetlane,
zapisywane w plikach ani przekazywane w argumentach poleceń. Pusty szkielet
`android-app/keystore.properties` utworzony przez bootstrap został usunięty;
kolejne buildy Gradle pozostają bez podpisu aż do osobnego kroku podpisania.

Przykład dla dokładnie tego unsigned APK (użyć nowej nazwy wyjściowej):

```bash
python3 tools/sign_apk_from_backup.py \
  android-app/app/build/outputs/apk/release/app-release-unsigned.apk \
  dist/recovery/app-3.4-next-check.apk \
  --sha256 6b915e9f505e4bd9f90717afdd695db4832ea0ae476ed61eae72a4aba1c2e5f6
```

Po nowym buildzie należy podać hash nowego wejściowego APK. Skrypt odmawia
podpisania pliku o innym hashu oraz nadpisania istniejącego wyniku; sprawdza
certyfikat przed podpisaniem, a potem weryfikuje podpis i niezmienioną zawartość.
Testy błędnego hasha i istniejącego wyjścia przeszły. Pełny powtórny przebieg
zapisanym skryptem również przeszedł i dał identyczny SHA-256 podpisanego APK
(`7ad72abf…`). Klucz i APK są poza Gitem; do repozytorium trafiają wyłącznie skrypt

pusty szkielet `keystore.properties` trzeba usunąć przed budowaniem bez podpisu;
nie usuwać pliku, jeśli zawiera już własną konfigurację.

FileVault nadal jest wyłączony (sprawdzone 25.09); jego włączenie i zachowanie

### Klucz: co pozostało

SSH do `hetz` działa. Pobrano backup z

Zainstalowano `pinentry-mac` i ustawiono
`pinentry-program /opt/homebrew/bin/pinentry-mac` w `~/.gnupg/gpg-agent.conf`.
GPG odrzucił podane hasło: `decryption failed: Bad session key`. Pliki tymczasowe
usunięto. **Nie odtworzono `.jks` ani nie utworzono `android-app/keystore.properties`;
inwentarz klucza pozostaje bez zmian.**

Po przygotowaniu prawidłowego hasła **archiwum GPG** ponowić:

```bash
./tools/bootstrap_build_machine.sh --key hetz
```

Hasło wpisać w oknie `pinentry`. Po udanym odtworzeniu skrypt utworzy prywatny
szkielet `android-app/keystore.properties` (ignorowany przez Git). **Osobno** trzeba
w nim lokalnie uzupełnić `storePassword` i `keyPassword` z menedżera haseł — hasło
archiwum i hasła JKS nie muszą być takie same. Następnie uruchomić
`./tools/bootstrap_build_machine.sh --build`.

Skrypt sprawdza teraz podpis APK i odcisk certyfikatu. Inny hash APK kończy się
kodem błędu, podobnie jak brak klucza, puste hasła lub JDK inny niż 21. Wywołanie
bez argumentów niczego nie zapisuje. Poprawiono również zapętlenie parsera przy
samym `--key` i sprzątanie po nieudanym odszyfrowaniu.
