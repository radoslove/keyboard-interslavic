### Klucz: co pozostało

SSH do `hetz` działa. Pobrano backup z
`claude@100.91.132.98:~/keystore-backup/medzuslovjansky-keystore-backup.tar.gpg`;
suma SHA-256 jest zgodna:
`01a836bc3fd60df222334d058eabffd0b735806c3a77b4ecc1fff853d6f43728`.

Zainstalowano `pinentry-mac` i ustawiono
`pinentry-program /opt/homebrew/bin/pinentry-mac` w `~/.gnupg/gpg-agent.conf`.
GPG odrzucił podane hasło: `decryption failed: Bad session key`. Pliki tymczasowe
usunięto. **Nie odtworzono `.jks` ani nie utworzono `android-app/keystore.properties`;
inwentarz klucza pozostaje bez zmian.**

Po przygotowaniu prawidłowego hasła **archiwum GPG** ponowić:

```bash
./tools/bootstrap_build_machine.sh --key hetz
```

Hasło wpisać w oknie `pinentry`. Po udanym odtworzeniu skrypt utworzy prywatny
szkielet `android-app/keystore.properties` (ignorowany przez Git). **Osobno** trzeba
w nim lokalnie uzupełnić `storePassword` i `keyPassword` z menedżera haseł — hasło
archiwum i hasła JKS nie muszą być takie same. Następnie uruchomić
`./tools/bootstrap_build_machine.sh --build`.

Skrypt sprawdza teraz podpis APK i odcisk certyfikatu. Inny hash APK kończy się
kodem błędu, podobnie jak brak klucza, puste hasła lub JDK inny niż 21. Wywołanie
bez argumentów niczego nie zapisuje. Poprawiono również zapętlenie parsera przy
samym `--key` i sprzątanie po nieudanym odszyfrowaniu.

## Instrukcja pierwotna (zachowana dla kontekstu)

Wszystko poniżej wykonuje się **na `mc`**. Nie trzeba wracać na `hp`.

Powód, dla którego to jest plik, a nie zdalne wykonanie: **Tailscale na `hp` nie
przepuszcza TCP**, więc z `hp` nie da się wejść po SSH ani na `mc`, ani na `hetz`.
Naprawa po stronie `hp` to `Restart-Service Tailscale` w PowerShellu jako administrator.

## Część A — klawiatura na `mc`

### A1. Pobierz zmiany

```bash
cd ~/Projects/keyboard-interslavic && git pull
```

### A2. Uruchom skrypt sprawdzający

Plik trafił do repozytorium jako `100644`, czyli bez bitu wykonywalności — `chmod +x`
zrobiony na Windowsie nie został zapisany, bo tamten system tego bitu nie przenosi.
Dlatego uruchamiamy przez `bash`, co ten problem omija:

```bash
bash tools/bootstrap_build_machine.sh
```

Ten przebieg **niczego nie zmienia** — tylko wypisuje, czego brakuje.

### A3. Napraw bit wykonywalności na stałe

Żeby to nie wracało na żadnej maszynie:

```bash
chmod +x tools/bootstrap_build_machine.sh
git update-index --chmod=+x tools/bootstrap_build_machine.sh
git commit -m "tools: make bootstrap script executable"
git push
```

### A4. Android SDK, jeśli A2 zgłosił brak

Temurin 21 jest już zainstalowany. ⚠ Musi zostać **21**, nie 26 — inny major potrafi
zmienić wynik builda, a cała ścieżka F-Droida stoi na tym, że APK jest odtwarzalny.

```bash
brew install --cask android-commandlinetools
sdkmanager "platform-tools" "platforms;android-34" "build-tools;34.0.0"
echo 'export ANDROID_HOME="$(brew --prefix)/share/android-commandlinetools"' >> ~/.zshrc
source ~/.zshrc
```

### A5. Odtwórz klucz podpisujący i zbuduj

```bash
./tools/bootstrap_build_machine.sh --key hetz --build
```

Skrypt ściągnie archiwum z `hetz`, sprawdzi jego sumę kontrolną i odcisk certyfikatu,
założy `keystore.properties` ze ścieżką właściwą dla macOS, zbuduje i porówna hash.

⚠ Hasło podajesz w okienku `pinentry`, z menedżera haseł. Skrypt nigdy go nie widzi
i nigdzie nie zapisuje. ⚠ Archiwum **nie może** pochodzić z `hp` — skrypt tego pilnuje
i odmówi, bo inaczej ćwiczenie niczego nie dowodzi.

**Wynik, na który czekamy:** `771f5dc9c2a0651b1e88f7b9227a446a1c8da59820ec45f3196120d1c7bc1863`
— ten sam hash co z `hp`. Jeśli się zgodzi, `hp` przestaje być pojedynczym punktem awarii,
a test reprodukowalności u F-Droida najpewniej też przejdzie.


⚠ Przy `git push` GitLab poprosi o nazwę użytkownika i hasło — hasłem jest
**personal access token**, nie hasło do konta.

### B2. Podmień pięć wartości

⚠ Nie edytuj tego pliku w przeglądarce ani ręcznie: w linii `Binaries:` jest **spacja
na końcu**, wymagana przez kanoniczny format `fdroid rewritemeta`, a edytory potrafią
ją obciąć. `sed` poniżej tej linii nie dotyka.

```bash
sed -i '' \
  -e "s/versionName: '3.1'/versionName: '3.3'/" \
  -e "s/versionCode: 31/versionCode: 33/" \
  -e "s/commit: c7833ff74843dfcad21c3550ce6f74a6a6d542ab/commit: a379b491797a106556390473395cf3a63d63d681/" \
  -e "s/CurrentVersion: '3.1'/CurrentVersion: '3.3'/" \
  -e "s/CurrentVersionCode: 31/CurrentVersionCode: 33/" \
  metadata/com.radoslove.interslavic.yml
```

Składnia `-i ''` jest macOS-owa; na Linuksie byłoby samo `-i`.

### B3. Sprawdź, czy weszło dokładnie pięć zmian

```bash
git diff
```

### B4. Wyślij
